# 红色档案智能体：后续功能技术文档

> 本文档用于 GitHub 协作开发规划，按“优先级 + 模块 + 验收标准”组织。  
> 当前项目已经跑通核心 RAG、多智能体、地图时间轴和知识图谱 MVP，后续重点是提升可信度、交互体验、工程质量与比赛竞争力。

---

## 1. 总体演进目标

把当前“能演示的 MVP”升级为“可协作、可评估、可扩展的智能体系统”。

主要方向：

1. 从字面检索升级到语义检索。
2. 从单文档答案升级到可溯源、可验证答案。
3. 从手工/少量图谱升级到自动构建 + 自动质检 + 人工小样本复核。
4. 从单次对话升级到持久化多轮记忆和用户画像。
5. 从单机 Flask 升级到更清晰的 API 服务和可复现部署。

## 2. 工程协作与代码治理

### 2.1 GitHub 仓库初始化

- 建立 `.gitignore`。
- 建立 `.env.example`。
- 建立 `docs/`、`tests/`、`scripts/`、`legacy/` 目录。
- 使用分支策略：`main`、`dev`、`feature/xxx`。
- 推荐 PR 流程：功能分支 → PR → Code Review → 合并。

### 2.2 配置与密钥管理

- 所有密钥走环境变量。
- 不提交 `data/ocr_output/` 和 `data/index/`。
- 知识图谱 JSON 体积小，可提交。
- 使用 `python-dotenv` 加载 `.env`，但 `.env` 不提交。

### 2.3 代码规范

- Python：统一使用类型注解、docstring。
- 前端：抽出重复 JS，拆分为模块。
- 格式化：推荐 `ruff format` 或 `black`。
- 提交信息：推荐 Conventional Commits。

## 3. 数据层升级

### 3.1 文本预处理增强

- 修复 OCR 常见错字表。
- 建立地名、人名、部队番号规范化词表。
- 保留页码、文件来源、章节信息，为溯源展示服务。

### 3.2 向量检索

当前是 TF-IDF，建议新增：

- 中文向量模型：`BAAI/bge-small-zh-v1.5`、`bge-large-zh-v1.5`。
- 向量库：Chroma、FAISS 或 Milvus Lite。
- 混合检索：BM25/TF-IDF + 向量 + RRF 融合。
- 增加 chunk 元数据：文件、页码、村寨、年份、部队。

### 3.3 检索评测集

- 准备 50–100 个标准问题。
- 标注标准答案、相关档案片段、村寨、年份。
- 指标：`recall@k`、`MRR`、`answer faithfulness`、`citation precision`。

## 4. 知识图谱升级

### 4.1 实体规范化与实体链接

- 建立权威实体库：人名、地名、部队、会议、战斗、渡口。
- 使用 LLM 将 OCR 抽取实体链接到权威 ID。
- 引入别名表、历史地名词典。
- 使用拼音/字形相似度做模糊匹配。

### 4.2 关系抽取优化

- 当前关系类型较少，建议扩展：
  - `commander`、`participant`、`occurred_at`
  - `located_in`、`part_of`、`preceded_by`
  - `fought_at`、`crossed_at`、`issued_order`
- 使用事件时序抽取：从日期文本生成 `before/after` 关系。
- 使用少样本 Prompt 或微调小模型降低抽取成本。

### 4.3 自动质检

- 多文档交叉验证：实体至少出现在两个文件才标记高置信。
- LLM 投票：同一 chunk 抽取 2–3 次，保留多数结果。
- 人工复核界面：Web 端可审阅 `review_required.json`，支持“通过/拒绝/改规范名”。
- 质检结果回写训练集，用于后续优化 Prompt。

## 5. Agent 升级

### 5.1 可溯源问答

- 每个关键事实都附带档案来源、文件、页码和原文片段。
- 前端支持点击来源定位到原文。
- 回答末尾生成结构化引用列表。

### 5.2 多轮记忆持久化

- 将对话历史存入 SQLite 或 Redis。
- 按会话 ID 管理，不同村寨和历史上下文隔离。
- 支持用户画像：兴趣地点、是否学生、是否旅游规划等。

### 5.3 工具调用增强

- 增加地图距离计算、旅行时间估算工具。
- 增加“生成研学路线”工具。
- 增加“同义词/别名扩展检索”工具。
- 增加“跨文档对比”工具，如“楚雄与曲靖的红军故事有何不同”。

### 5.4 多智能体协作

- 设置检索 Agent、图谱 Agent、旅游规划 Agent、事实校验 Agent。
- 对复杂问题使用规划-执行-验证循环。
- 对冲突证据使用辩论机制：多个校验 Agent 给出结论，最终由主控 Agent 综合。

## 6. 前端与交互升级

### 6.1 地图与时间轴联动

- 点击时间轴自动走到对应地点。
- 播放长征路线动画。
- 显示部队番号、日期、关键事件气泡。

### 6.2 数字人体验

- 头像从静态图升级为口型同步或 Live2D。
- 支持播放/暂停/倍速语音。
- 方言语音优先，必要时训练或采购本地音色。

### 6.3 知识图谱交互

- 节点点击显示详情卡片。
- 支持按实体类型、年份、部队过滤。
- 支持双击展开邻居节点。
- 支持图谱与地图联动：点击地点节点，地图飞到对应村寨。

### 6.4 溯源与原文阅读

- 在回答中高亮引用的档案句子。
- 提供“查看原文”浮层，显示 OCR 原文扫描件或 TXT 片段。
- 提供证据可信度颜色标记。

## 7. 评测与比赛展示

### 7.1 自动评测

- 构建 RAG 评测集。
- 使用 LLM-as-a-Judge 评估回答相关性、忠实度、完整性。
- 自动记录每次运行的结果，生成对比报告。

### 7.2 演示脚本

- 准备 5 分钟演示路径：
  1. 地图选择村寨。
  2. 提问一个档案事实。
  3. 展示规划与工具调用。
  4. 展示知识图谱。
  5. 展示事实校验。
- 准备“有挑战的问题”：
  - 对比两条路线。
  - 规划研学路线。
  - 追问某个历史细节。

## 8. 部署与服务化

### 8.1 API 服务升级

- 保留 Flask 或迁移 FastAPI。
- 增加 `/health`、`/metrics`。
- 增加流式返回：SSE 或 WebSocket。
- 增加请求日志和异常监控。

### 8.2 容器化

- 编写 `Dockerfile`。
- 编写 `docker-compose.yml`。
- 将模型缓存和数据目录挂载到宿主机。
- 提供一键启动脚本。

### 8.3 安全与合规

- 限制 CORS。
- API 限流。
- 防止提示注入。
- 档案版权和数据隐私评估，尤其涉及比赛公开展示时。

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| OCR 错字过多 | 增加纠错表、多文档投票、实体链接 |
| LLM 幻觉 | 事实校验、溯源引用、限制知识边界 |
| 图谱抽取不稳定 | 小批量抽取、自动质检、人工复核 |
| 数据版权 | OCR 文本不上传 GitHub，演示时说明来源 |
| 依赖环境复杂 | Docker、requirements 锁版本、一键脚本 |
