## 3.1 技术可行性分析

### 3.1.1 数据采集

本项目数据源为**云南省档案馆馆藏红军长征档案文献**，共 **18 部**（PDF 扫描件为主，合计约 405 MB），涵盖：

- **红军视角**：党史资料汇编、亲历者回忆录（刘伯承《回顾长征》、陈云《随军西行见闻录》等）
- **国民党视角**：《国民党军追堵红军长征档案史料选编（云南部分）》（云南省档案馆编，628 页，含滇军追堵部署、龙云与蒋介石往来电文）
- **民众视角**：革命故事、歌谣集（《乌蒙磅礴走泥丸》等）

数据获取方式：档案文献经 OCR（扫描件）与 PyMuPDF 文本提取（文字版）转为纯文本，共约 **980 万字符**；经繁体转简体（OpenCC）、错字纠错、语义分块后构建 **9,132 个索引文本块**。原始 PDF 与 OCR 文本因版权与体积原因不对外分发，仅结构化产物（索引、知识图谱、篇目目录）入库。

### 3.1.2 行业知识获取

历史知识的权威性依赖两条渠道：

1. **档案原文**：所有回答的事实锚定于 OCR 档案文本，检索层（TF-IDF 字符级 2-4 元语法）与 LLM 生成层双重约束，避免"历史幻觉"。
2. **专家整理的档案目录**：《红军长征过云南相关档案文献目录》（18 部书、**1,225 条篇目名与对应页码**），由党史资料机构整理，作为"某书某页"级溯源的权威依据，解析为结构化资产 `data/knowledge_graph/book_toc.json`。

村寨词表（皎平渡、扎西、寻甸柯渡等 40 个地点）与知识图谱基础实体（56 个）依据档案与党史通说手工整理，经自动校验脚本（实体频次、名称规范化、LLM 真实性复核）与人工抽查确认。

### 3.1.3 算力与硬件支持

- **检索与图谱**：TF-IDF（9,132 × 3,000 维）与 JSON 图谱查询均为 CPU 轻量计算，普通笔记本即可运行，无 GPU 依赖。
- **LLM 推理**：通过 DeepSeek API（OpenAI 兼容接口）调用，需要网络与 API 额度；单轮问答 Token 成本低（检索 + 生成 + 可选事实校验）。
- **语音合成**：edge-tts（网络）/ Windows 本地 SAPI（离线兜底）/ 浏览器 SpeechSynthesis（最终兜底）三级降级，无专用硬件要求。

结论：数据可获得、行业知识有权威来源、算力门槛低，技术上完全可行。

## 3.2 技术细节

### 3.2.1 数据治理流水线

```text
18 部 PDF 档案
  ├─ 扫描件 → OCR（PaddleOCR 流程） / 文字版 → PyMuPDF 提取
  ├─ 繁体转简体（OpenCC）
  ├─ OCR 高频错字纠错表（53 条整词替换，如 周付主席→周副主席、金小江→金沙江）
  ├─ 错字变体自动扫描（以 45 个专名为锚，全库检索相似形态 94 个候选，人工筛选并入纠错表）
  └─ 语义分块（合并 OCR 碎行 → 500 字语义块，9,132 块）
       └─ TF-IDF 字符级 2-4 元语法索引（3,000 维）+ 村寨地点倒排
```

**数据质量量化**（抽样 1,000 字人工复核）：高置信错字率约 2.5%–3%；质量较差的扫描件封面错字率可达 8%–10%。已通过纠错表 + 字符级 n-gram 检索容忍治理；关键事实仍以档案原文锚定，LLM 生成时受证据约束。

### 3.2.2 档案知识图谱构建

- **实体与关系**：473 个实体、282 条关系（commander、occurred_at、next_on_route、participant、alias 等 10 类），经自动校验（无悬空引用、无重复 id、无缺描述）与实体消歧（同名合并、近名人工确认）保证质量。
- **自动抽取**：`extract_entities.py` 支持 LLM / 规则两种抽取模式，输出合并预览后经 `validate_entities.py` 频次 + LLM 双重校验，只提交确认实体（可扩展至 500+ 实体规模）。
- **可扩展性**：图谱以 JSON 存储，上层查询接口（`KnowledgeGraphStore`）统一供 Agent 工具与 Web 可视化调用，后续可平滑迁移 Neo4j / LightRAG。

### 3.2.3 溯源体系（"某书某页"级）

| 字段 | 说明 | 覆盖率 |
|---|---|---|
| source | 档案名（如《金沙江的记忆》） | 9,132/9,132 |
| offset | 源文件字符偏移（文本定位） | 9,132/9,132 |
| section | 篇目名（如"巧渡金沙江（萧应棠）"，来自 1,225 条篇目目录） | 9,132/9,132 |
| page | 篇目对应页码（档案目录权威数据） | 9,132/9,132 |
| confidence | exact（正文标题精确锚定）/ approx（页码比例插值） | exact 495 / approx 8,637 |

溯源实现双方案：①**精确锚定**——在 OCR 正文中定位篇目标题（自动跳过目录页、检测"篇目名后跟页码"的目录项特征），适用于 OCR 质量好的档案；②**近似插值**——按"篇目页码区间 + 文本比例"估算（实测误差 2–5 页，篇目归属准确），全量兜底。

### 3.2.5 检索效果实测（60 题评测集）

为支撑"AI 推理效果与指标"评审要求，构建了 **60 道问答题**的检索评测集（覆盖事件/人物/地点/综合路线，含村寨限定），实测检索基线如下：

| 指标 | TF-IDF 基线 | Hybrid (RRF) |
|---|---|---|
| hit@1 | 80.0% | **88.3%** |
| hit@3 | 90.0% | 90.0% |
| hit@5 | 91.7% | **93.3%** |
| MRR | 0.843 | **0.896** |

> 说明：Hybrid 为字符 TF-IDF + 词级 TF-IDF 双路 RRF 融合；评测集 60 题均已标注 `gold_chunk_ids`。
> 混合检索已接入 Agent 全链路（`retriever_factory.create_retriever()`）。
